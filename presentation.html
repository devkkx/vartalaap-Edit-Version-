SLIDE 3 OF 6 — FLOW STRUCTURE

HOW IT WORKS: End-to-End System & Data Flow Structure

1. User Registration & Email OTP Flow

User inputs Gmail address → Spring Mail dispatches 6-digit OTP → User verifies via /auth/verify-otp → Password fields unlock (6-32 chars) → Account saved in MySQL.

2. STOMP Socket Connection Setup

Browser opens TCP socket to ws://localhost:8081/chat → Upgrades to STOMP protocol → ChatHandler maps session → Broadcasts JOIN:username system notice.

3. Message Transmission & Database Persistence

Sender transmits payload (mode|sender|text) → ChatHandler saves Message in MySQL → Auto-assigns DB id → Broadcasts mode|sender|text|id over WebSocket.

4. Real-Time 3-Dots Live Edit & Delete Sync

Message renders with 3-dots (⋮) → Edit sends PUT /messages/{id} (broadcasts EDIT|id|text); Delete sends DELETE /messages/{id} (broadcasts DELETE|id) → Live DOM update.
